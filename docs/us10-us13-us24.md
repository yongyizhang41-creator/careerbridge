# Job cart, hiring pipeline, and content reports

Contributor: Yinuo Chen (GitHub: EGC-TB).

These features extend the existing Django application without changing the application,
profile, messaging, search, or moderation data contracts.

## Setup

Use the existing Python environment and requirements. No new dependencies are required.

```bash
python manage.py migrate
python manage.py test
python manage.py runserver
```

The new migrations add `jobs.CartItem` and `reports.Report`. Existing applications and
stages are not rewritten. Local duplicate source files are not migrations; keep backups
outside app directories (for example, the ignored `tmp/local-backups/` directory).

## US10: comparison cart

Job seekers add a job from its search result or detail page. `/jobs/cart/` stores items by
account with a database uniqueness constraint on `(owner, job)`. Select two or more jobs
and compare their company, location, work arrangement, salary range, visa sponsorship,
skills, description, and posting date. Comparison only accepts items from the signed-in
user's cart. Unavailable jobs cannot be added, compared, or applied to. They remain
removable from the cart. A permanently deleted job is removed by the foreign-key cascade.

Saving a job is not applying. The comparison page links back to the existing job detail
and application form, preserving personalized notes and duplicate-application protection.
Already-applied jobs are labeled, and removing a saved item does not remove an application.
Cart contents persist across sessions.

## US13: hiring pipeline

Recruiters open `/jobs/pipeline/` from their workspace, job list, or applicant list. It
shows only their applicants in Applied, Review, Interview, Offer, and Closed columns.
An optional owned-job filter includes removed jobs so existing hiring records remain
manageable. Each card links to the existing candidate and application detail page.

Drag a card between columns, or choose a stage and save. The form also works without
JavaScript. Both update the existing `Application.status` field, so the original status
editor and job-seeker tracking page stay synchronized. The new move endpoint validates
roles, ownership, stage choices, CSRF, and the expected previous stage. A conditional
update rejects stale moves without overwriting another change. It does not change notes,
applicants, or jobs.

## US24: reports and investigation

Signed-in users report an active job from its detail page, or another active user from
the posting-account, candidate-application, or private-conversation entry point. A report
contains a reason, details, reporter, target, timestamp, and content snapshot. A snapshot
preserves submitted evidence if the target changes or is deleted. User snapshots contain
username and role, not passwords, contact details, or private conversation history.

Reporting a job seeker requires profile visibility, an application to the reporter's
job, or an existing conversation with the reporter; administrators can report any
other active user. Unrelated users receive 404 without the candidate's username.
An existing Pending or Investigating report by the same reporter for the same target
prevents another submission. A new report is allowed after the previous one is Resolved.

Only administrators can access `/reports/`, filter/search the paginated report queue,
read evidence, or save investigation notes and a Pending / Investigating / Resolved
status. Resolving requires notes. The reviewer and review time are recorded. Reporters
and reported users cannot access investigation pages unless they have administrator
privileges.

Reviewing or resolving a report does not automatically suspend an account or remove a
job. An explicit removal button for active jobs uses the existing administrator-only,
CSRF-protected POST action and redirects to job moderation, where removal can be undone.
Links lead to existing job moderation and the existing CareerBridge user-management
pages. User management links require staff access and the appropriate view or change
permission. Those tools retain their existing permission rules.

## Validation

`jobs/test_cart_pipeline.py` covers persistence, ownership, comparison, removed jobs,
application integration, pipeline grouping, stale moves, role restrictions, and CSRF.
`reports/tests.py` covers submission, private review, evidence preservation, filtering,
resolution, existing management links, role restrictions, and CSRF. The original test
suite also runs to check compatibility with profile, application, CSV, and messaging flows.
`reports/test_fixes.py` covers candidate privacy, duplicate reports, and explicit job
removal while preserving the existing moderation permissions and CSRF protection.
