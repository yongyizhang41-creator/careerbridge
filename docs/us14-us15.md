# Recruiter messaging and email

## US14: message candidates inside CareerBridge

This story was already implemented in `communications` before this change: private
recruiter/candidate conversations, replies from either participant, unread counts,
and a chronological message history. Only the two participants can read or reply.
Messages stay inside CareerBridge and do not send email or expose personal email
addresses in the conversation.

Recruiters can now start a conversation from candidate search results and recommended
candidate profiles as well as applicant lists and application reviews. Direct contact
URLs enforce the candidate's privacy settings: an active job seeker must have opted
into recruiter discovery, applied to one of this recruiter's jobs, or already have a
conversation with this recruiter. An application still grants contact access when
the candidate has no profile. A conversation remains accessible after discovery is
disabled.

## US15: email candidates through CareerBridge

Choose **Email candidate** from candidate search, a recommended candidate's profile,
an applicant list, an application review, or an existing conversation. Write a subject
and message, then choose **Send email**. This sends plain text to the candidate's
account email using Django's SMTP backend. It does not create an in-platform message.

The platform supplies the sender and recipient; form fields cannot change them.
The email identifies the recruiter and sets Reply-To to their account email so the
candidate can reply in their own email client. Both accounts need valid email addresses;
an administrator can update missing addresses through User management. The composer
shows the candidate's recipient address and the recruiter's reply address before sending.

Blank/oversized messages and multiline subjects are rejected. Only a recruiter with
contact access can send, and sending requires a CSRF-protected POST. SMTP errors retain
the draft without showing server credentials or internal error messages. Success means
the mail server accepted the message; it does not guarantee inbox delivery or track
bounces, and sent emails are not archived in CareerBridge.

### SMTP setup

The website's sender is `careerbridgemessage@gmail.com`. Gmail's SMTP hostname,
port 587, and STARTTLS are configured by default. Only its Google app password is
needed on each machine that runs the app.

1. Sign into that Google account, enable 2-Step Verification, and create an app
   password named **CareerBridge** at <https://myaccount.google.com/apppasswords>.
2. On the computer or hosted server running CareerBridge, activate the project's
   Python environment and run:

   ```bash
   python manage.py configure_email
   ```

3. Paste the app password into the hidden terminal prompt. The command verifies
   the SMTP sign-in without sending email, then saves it to `.smtp-password` in
   the project root. This file is ignored by Git and readable/writable only by
   its owner on macOS/Linux. An invalid password leaves any existing file intact.
4. Restart the local Django server, or reload the existing PythonAnywhere web app.
   Send a test email through **Email candidate** to a mailbox you can check.

Do not paste the password into chat, commit it, or use the Google account's normal
password. The demo presenter does not need to sign into the sender's Gmail account.
They do need access to the recipient mailbox to demonstrate delivery. If the app
runs on another machine, run setup on that machine too; Git does not transfer secrets.

The private password file loads automatically. Alternatively, configure these
environment variables in the Django server process (for PythonAnywhere, set them
in the WSGI configuration before Django loads). Existing environment variables
take precedence over defaults and the password file. A local `.env` file is not
automatically loaded. Restart/reload the server after changing settings.

| Variable | Value |
| --- | --- |
| `EMAIL_HOST` | `smtp.gmail.com` by default |
| `EMAIL_PORT` | `587` by default |
| `EMAIL_HOST_USER` | `careerbridgemessage@gmail.com` by default |
| `EMAIL_HOST_PASSWORD` | App password; overrides `.smtp-password`, even when explicitly empty |
| `DEFAULT_FROM_EMAIL` | Defaults to `EMAIL_HOST_USER` |
| `EMAIL_USE_TLS` | `True` by default, for STARTTLS on port 587 |
| `EMAIL_USE_SSL` | `False` by default; use `True` with port 465 and `EMAIL_USE_TLS=False` for implicit TLS |

Use the platform's mail credentials for these settings. Recruiters do not enter their
personal mailbox passwords. Providers that disable password-based SMTP require an
approved SMTP relay or a provider that supports this authentication method. Outbound
SMTP must also be allowed by the hosting service. Keep credentials outside Git.

Until the password is supplied, sending is disabled with an explanation and a link
to platform messaging. There is no console-only delivery fallback
that reports success without sending email. No schema changes or new dependencies are
needed.

### Validation

```bash
python manage.py check
python manage.py makemigrations --check --dry-run
python manage.py test
```

`communications/tests.py` checks the existing messaging flow. `communications/test_email.py`
checks email composition, server-bound headers, recipient privacy, both contact methods'
visibility rules, authorization, CSRF, input validation, missing configuration, draft
preservation, failure handling, and SMTP configuration. Tests use Django's in-memory
outbox or a mocked SMTP transport; they send no real email. Confirm delivery to a test
mailbox after configuring the deployed SMTP service.

`communications/test_email_setup.py` verifies private credential storage, sign-in
failure handling, hidden-input enforcement, and server-environment precedence.
